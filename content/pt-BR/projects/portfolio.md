A maioria dos portfólios de desenvolvedor é um currículo disfarçado de site: uma página estática que lista empregos e habilidades e torce para que o recrutador leia até o fim e note a pessoa por trás dela. Esse foi o problema de partida — um portfólio parecido com qualquer outro, que não dizia nada sobre como seu autor realmente trabalha.

O objetivo aqui não era construir um panfleto maior. Era construir um produto pequeno com a mesma disciplina de um produto de verdade, e deixar o próprio site ser a prova disso: internacionalização real em vez de um seletor de idioma emendado depois, uma arquitetura documentada em vez de conhecimento tácito, um pipeline de release automatizado em vez de versão trocada manualmente, e conteúdo que vive em arquivos de dados em vez de texto fixo espalhado pelos componentes — para que o site cresça do jeito que um código de verdade cresce, não do jeito que uma página estática é remendada.

A inspiração foi mais prática do que estética: cada escolha feita aqui — o roteamento por idioma, o texto vindo de dicionários, os checks de CI, os commits convencionais alimentando um changelog automático — é uma escolha que um time de contratação reconheceria de um código em produção, porque foi construída do mesmo jeito. As métricas de tempo de código e linguagens nesta própria página não são decorativas; vêm ao vivo das ferramentas realmente usadas na construção do site, então a história que o site conta sobre sua própria construção é comprovável, não só afirmada.

Como portfólio, é justo dizer que não há muito "problema de domínio" a resolver — sem usuário para integrar, sem regra de negócio para cumprir. O que vale registrar em vez disso é o formato do processo: este projeto existe como o primeiro registro e o modelo de trabalho para os que vierem depois dele. Todo projeto novo adicionado aqui deveria conseguir apontar de volta para este e dizer: essa é a régua — documentado, internacionalizado, medido, e honesto sobre o que é.
